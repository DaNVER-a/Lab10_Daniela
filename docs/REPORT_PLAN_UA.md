# План індивідуального звіту — лабораторна №10

**Студент:** Вергуненко Даніела Сергіївна  
**Група:** ФІТ-3-17  
**Предметна область:** Робота кол-центру

1. **Титульний аркуш.** Кафедра, тема, студент, група, рік.
2. **Мета роботи.** Інтегрувати GoF-патерни State, Strategy, Observer, Command у проєкт лабораторної №8 зі збереженням Repository/ORM/SQLite.
3. **Початкова архітектура.** Сутності та зв'язок 1:N, Repository, попередні операції з базою даних.
4. **State.** Конкретні класи станів, допустимі переходи `Registered → Accepted → Completed; окремо Cancelled`, спроба забороненого переходу, збереження історії та транзакційна цілісність.
5. **Strategy.** Параметри: важливість, терміновість, час очікування. Показати чисельні результати всіх трьох алгоритмів із власного запуску.
6. **Observer.** Продемонструвати два види подій, журнал, підрахунок статистики та відключення підписника.
7. **Command.** Пояснити призначення `ICommand`, `TransitionCommand`, `CommandInvoker` для послідовного виконання дій.
8. **Діаграми.** Приклади Mermaid наведено в `DIAGRAMS.md` (їх можна відобразити у diagrams.net або GitHub та вставити у Word).
9. **Тестування.** Таблиця тестів: допустимий/недопустимий перехід, rollback з ін'єкцією помилки, три стратегії, Observer subscribe/unsubscribe, Command, перевірка SQLite/ORM.
10. **Результати запуску.** Вставити отримані скриншоти з Visual Studio, не вигадувати час, коди помилок або дані.
11. **ШІ при виборі патерну (вимога методички).**

   - Система: ChatGPT, модель GPT-6.
   - Запит: «Запропонуй додатковий патерн GoF для розширення системи 'Робота кол-центру' з використанням State, Strategy, Observer, Repository та SQLite. Порівняй Command, Factory Method і Decorator за відповідністю архітектурі».
   - Рекомендації: Command для інкапсуляції дій, Factory Method для централізації створення об'єктів, Decorator для додавання поведінки без зміни класів.
   - Запропонований вибір: **Command**, тому що він відокремлює запуск операцій від бізнес-сервісу й дозволяє формувати чергу команд.
   - Студент має самостійно перевірити запропоноване рішення, обґрунтувати вибір та описати власну участь. Не видавати цей текст за дослівну історію розмови, якщо фактичний запит відрізнявся.

12. **Висновки.** Обґрунтувати розділення відповідальностей, транзакційну цілісність і результати модульних тестів.
